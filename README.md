# かたち合わせ（試作）

オーダーメイドのバッグについて、お客様と作家の間で「どの寸法か」「何を変更したか」を図で確認するための Web アプリです。
対象は「底の角をつまんでマチを作る、シンプルな船底型トートバッグ」1種類です。販売需要を検証するための試作です。

- サーバー・ログイン・外部 API・クラウド DB は使いません。入力内容は端末の外へ送信しません。
- 外部 CDN・Web フォント・画像素材に依存しません（図はコードで描画、文字は端末の日本語フォント）。
- iPad Safari を主な対象とし、iPhone でも使えるレスポンシブ構成です。

## 構成

```
docs/               ← 公開するファイル一式（静的ホスティングにそのまま置く）
  index.html
  css/app.css
  js/model.js       寸法の正規化・検証・底幅計算・変更判定・JSON検証
  js/diagram.js     模式図（SVG表示とPNG書き出しで共通の描画命令）
  js/report.js      確認画像の内容（お客様用・作家用）を共通データから組み立て
  js/export.js      確認画像（PNG）の描画とページ分け
  js/storage.js     端末内保存（使えなくても動作継続）
  js/edition.js     版の設定（公開体験版／購入者用。ここだけが版によって異なる）
  js/app.js         画面の操作
  manual.html       使い方（体験版・購入者用で共通）
scripts/build.mjs   購入者用の配布物を build/ に作る（build/ は git 管理外）
product/            販売説明の下書き、配布と公開の手順、購入者向け README の元
scripts/serve.mjs   確認用の簡易サーバー（依存パッケージなし）
tests/unit/         計算・変更判定・図の単体テスト（node:test）
tests/e2e/run.mjs   ブラウザ操作テスト（Playwright + Chromium）
```

ビルド手順はありません。依存パッケージもありません（ブラウザテストのみ Playwright を使用）。

## 公開体験版と購入者用

- `docs/` は**公開体験版**です（架空のサンプルで始まり、確認画像の上下に「体験版・サンプル」の帯が入ります）。
- 購入者用は `node scripts/build.mjs` で `build/` に作ります。`docs/js/edition.js` の版の設定行だけを差し替え、ほかのコードは共通です。1ファイル版と配布 ZIP も作ります。
- 体験版と購入者用は、ブラウザ内の保存場所を分けています（同じドメインで開いても混ざりません）。
- これは表示と保存場所を分ける仕組みで、購入者の認証やコピー防止ではありません。詳しくは `product/配布と公開の手順.md`。

## 起動・プレビュー

Node.js 18 以上がある環境で:

```
npm start            # http://localhost:8080/ で docs/ を配信
npm test             # 単体テスト
npm run build        # 購入者用の配布物を build/ に作る
npm run test:e2e     # ブラウザ操作テスト（購入者用を作ってから実行。Playwright が必要。結果の画像は test-output/）
```

JavaScript モジュールを使うため、HTML ファイルを直接開く（file://）のではなく、Web サーバー経由で開いてください。

## 静的ホスティングへの配置

`docs/` フォルダの中身をそのまま配置すれば動きます（Netlify、Cloudflare Pages など、どこでも可）。

GitHub Pages の場合（iPad のブラウザだけで設定できます）:

1. GitHub でこのリポジトリを開き、Settings → Pages を開く
2. 「Build and deployment」の Source を「Deploy from a branch」にする
3. Branch でこのアプリのあるブランチを選び、フォルダを `/docs` にして Save
4. 数分後に表示される URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）を Safari で開く

※ 非公開リポジトリで GitHub Pages を使うには有料プランが必要な場合があります。公開される URL は誰でも開けますが、入力した内容は各自の端末内にだけ保存され、サーバーには送られません。

## 主な仕様メモ

- 寸法は 0.1cm 単位の整数に正規化して扱います（`40` と `40.0`、全角数字も同じ値）。
- 空欄（未入力＝要確認）と `0` は区別します。
- 底幅 = 袋口幅 − マチ（この形のバッグに限った関係）。マチ ≥ 袋口幅はエラーとし、底幅を計算しません。
- 版番号：最初は版1。「比較元として保存」で、その時点の内容を比較元（版N）として固定し、以降の編集は版N+1 になります。
- 「比較元として保存」はお客様の承認を意味しません（画面・画像にもその旨を記載）。
- バックアップ JSON には `schema_version`（現在 2）、現在の内容、比較元、版番号、出力設定を含みます。読み込み時に形式と値を検証し、失敗しても既存の内容は変更しません。
- `schema_version: 1`（最初の試作）も読み込めます。ない項目は「お客様に確認したいこと＝空欄」「出力設定＝お客様用・追加図なし・メモなし」とし、注文内容と比較元はそのまま使います。
- 確認画像は「お客様用（かんたん）」が標準、「作家用（詳細）」も選べます。どちらも report.js の同じデータから作ります。長い場合は「図と変更点」「詳細」の複数枚に分けます。
- 変更の強調（オレンジ）は寸法線・ラベル・外側の囲みだけに使い、バッグや持ち手・ポケットの色には使いません。
- 比較の件数は「仕様変更一覧の行数」です（画面・確認画像とも `compareOrders` の同じ結果）。注文メモ・確認文・注文番号の変更は「文章の変更」として別に示し、件数に含めません。
- 保存前プレビューの各画像に「画像を保存」「拡大して確認」「共有（対応環境のみ）」があります。拡大表示は表示倍率だけを変え、書き出す画像は変わりません。
